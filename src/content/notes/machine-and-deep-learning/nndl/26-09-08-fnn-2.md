——用 PyTorch autograd 重做两层 MLP：小批量梯度下降 + 多分类交叉熵 + 鸢尾花三分类

承接 [NNDL 26-09-08 前馈神经网络练习（第一部分）](/notes/machine-and-deep-learning/nndl/26-09-08-fnn-1/)：上一部分用 `Op` 类手写两层 MLP，自己推导并实现每一层的反向传播；这一部分**把求导交给 PyTorch autograd**，把全批量 GD 换成**小批量（mini-batch）**，损失从二分类 BCE 换成**多分类交叉熵 + softmax**，数据从 `make_moons` 换成 **Iris 三分类**。练习目标：分清"框架接管了什么、自己还必须管什么"，并亲手复现**过拟合的 U 形曲线**。

# 一、公式总结

**记号**：批量 $\boldsymbol X\in\mathbb R^{N\times M}$（$M=4$ 个特征）、隐藏层宽度 $H=16$、类别数 $C=3$。层标 $^{(l)}$ 同第一部分：$(1)$=隐藏层、$(2)$=输出层。损失记 $\mathcal R$；$\delta\boldsymbol A=\partial\mathcal R/\partial\boldsymbol A$ 为上游传来的梯度。

**前向**（隐藏层激活为 Logistic，输出层是 softmax 概率）：

$$
\boldsymbol Z^{(1)}=\boldsymbol X\boldsymbol W^{(1)}+\boldsymbol b^{(1)},\qquad \boldsymbol A^{(1)}=\sigma\big(\boldsymbol Z^{(1)}\big),\qquad \boldsymbol Z^{(2)}=\boldsymbol A^{(1)}\boldsymbol W^{(2)}+\boldsymbol b^{(2)}
$$

$$
\hat y_{nc}=\frac{\exp\big(z^{(2)}_{nc}\big)}{\sum_{c'=1}^{C}\exp\big(z^{(2)}_{nc'}\big)}
$$

> 代码里 `forward` **返回的是 $\boldsymbol Z^{(2)}$（logits），不是 $\hat{\boldsymbol Y}$**：`nn.CrossEntropyLoss` 内部自己带 `log_softmax`，喂概率进去等于算了两遍。要画概率图时得自己补一次 `softmax`（图 2 的 `probs_std` 就是干这个的）。

**损失**（多分类交叉熵 = 正确类别预测概率的负对数均值，是第一部分二分类 BCE 的推广）：

$$
\mathcal R=-\frac{1}{N}\sum_{n=1}^{N}\log \hat y_{n,y_n}
$$

**① softmax + 交叉熵的合成梯度**（对比第一部分要分两步走）：

$$
\delta\boldsymbol Z^{(2)}=\frac{\partial\mathcal R}{\partial\boldsymbol Z^{(2)}}=\frac{1}{N}\Big(\hat{\boldsymbol Y}-\boldsymbol Y_{\text{one-hot}}\Big)
$$

> 第一部分里"① 损失对输出求导"+"② sigmoid 的逐元素门"是两步；这里 softmax 与 CE 合并后，梯度直接就是"**预测减标签**"，干净得不像话。

**② 隐藏层激活反向**（第一部分 ②，现在整段由 autograd 完成）：

$$
\delta\boldsymbol Z^{(1)}=\boldsymbol A^{(1)}\odot\big(1-\boldsymbol A^{(1)}\big)\odot\delta\boldsymbol A^{(1)}
$$

**③ 线性层反向**（第一部分 ③，注意参数梯度的转置方向）：

$$
\delta\boldsymbol W=\boldsymbol X^{\mathsf T}\delta\boldsymbol Z,\qquad \delta\boldsymbol b=\boldsymbol 1^{\mathsf T}\delta\boldsymbol Z
$$

**④ 小批量更新**（对比第一部分的 ⑤ 全批量；$B=16$，一个 epoch 更新 $N/B$ 次，$N=105$ 时约 7 次）：

$$
\boldsymbol\theta\leftarrow\boldsymbol\theta-\eta\cdot\frac{1}{B}\sum_{n\in\mathcal B}\frac{\partial\mathcal R_n}{\partial\boldsymbol\theta}
$$

**⑤ autograd 到底做了什么**：前向时框架把每个算子记进计算图；`loss.backward()` 沿图**逆序**调用各算子的反向函数，把 $\partial\mathcal R/\partial\theta$ **累加**到 `param.grad`（是 `+=` 不是 `=`）。所以三步的顺序是硬约束：

$$
\texttt{optimizer.zero\_grad()}\ \Longrightarrow\ \texttt{loss.backward()}\ \Longrightarrow\ \texttt{optimizer.step()}
$$

> 记忆点：**忘记 `zero_grad()` = 梯度跨 batch 累加**，等效于"学习率越来越大且方向是历史平均"；这和第一部分"BCE 反向少乘 $1/N$ → 梯度整体放大 N 倍"是同一类坑，只是这次是框架帮着踩的。

**⑥ 手写 vs autograd 对照**（同一套数学，两种实现）：

| 环节 | 第一部分（手写 Op） | 第二部分（autograd） |
|---|---|---|
| 前向 | 手工串 `fc → Logistic → fc → Logistic` | `fc1 → sigmoid → fc2` |
| 存中间量 | 每层自己存 `self.inputs` / `self.outputs` | 计算图自动记录，不用管 |
| 反向 | 自己写每个算子的 `backward`，按**逆序**手工调用 | 一句 `loss.backward()` |
| 参数 / 梯度 | `params` / `grads` 两个 dict | `nn.Parameter` + `.grad` |
| 更新 | `BatchGD.step()` 遍历 dict | `optim.Adam(...).step()` |
| 优化器 | 纯 SGD | Adam（一阶动量 + 二阶矩自适应） |
| 批量 | 全批量（一次喂完 799 条） | mini-batch（`DataLoader`，$B=16$） |
| 损失 | 二分类 BCE，输出过 sigmoid | 多分类 CE，输出 **logits** |

## 2.2 模型定义：`MLP`

```python
# MLP with torch
class MLP(nn.Module):
    def __init__(self,input_size=4,hidden_size=16,output_size=3):
        super().__init__()
        self.fc1 = nn.Linear(input_size,hidden_size)
        self.fc2 = nn.Linear(hidden_size,output_size)
        self.ac = torch.sigmoid

    def forward(self,inputs):
        z1 = self.fc1(inputs)
        a1 = self.ac(z1)
        z2 = self.fc2(a1)
        return z2
```

> `forward` 必须返回 `z2`（logits）。返回 `a1` 就是第三部分坑 3：`CrossEntropyLoss` 会把 16 维隐藏层激活当成 16 分类，`fc2` 连计算图都进不去（`grad is None`），而且**完全不报错**。

## 2.3 训练骨架：`Runner` 类

> 下面这版已经修掉了第三部分的坑 4 与坑 5：损失与指标都**按样本数加权**（`* y.size(0)`），并且补上了 `Train_score` 的统计——所以 `history` 里的 train / dev 四条曲线口径一致，可以直接叠在一张图上比。

```python
# runner
class Runner():
    def __init__(self,model,optimizer,loss_fn,metric):
        self.model = model
        self.optimizer = optimizer
        self.loss_fn = loss_fn
        self.metric = metric
        self.history = {
            'Train_score':[], 'Train_loss':[],
            'Dev_score':[], 'Dev_loss':[]
        }

    def train(self,train_loader,dev_loader,num_epochs):
        for epoch in range(num_epochs):
            self.model.train()
            running,running_score,n = 0.,0.,0
            for batch in train_loader:
                *inputs , y = tuple(t for t in batch)
                self.optimizer.zero_grad()
                out = self.model(*inputs)
                loss = self.loss_fn(out,y)
                loss.backward()
                self.optimizer.step()
                running += loss.item() * y.size(0)
                # 顺便统计训练集指标：与 evaluate() 一样按样本数加权
                running_score += self.metric(out.detach(),y) * y.size(0)
                n += y.size(0)
            train_loss = running / n
            self.history['Train_loss'].append(train_loss)
            self.history['Train_score'].append(running_score / n)
            dev_loss,dev_score = self.evaluate(dev_loader)
            self.history['Dev_loss'].append(dev_loss)
            self.history['Dev_score'].append(dev_score)

    @torch.no_grad()
    def evaluate(self,loader):
        self.model.eval()
        loss , score, n = 0.,0.,0
        for x,y in loader:
            out = self.model(x)
            loss += self.loss_fn(out,y).item() * x.size(0)
            n += x.size(0)
            score += self.metric(out,y) * x.size(0)
        dev_loss = loss / n
        dev_score = score / n
        return dev_loss,dev_score
```

**逐段读**：`*inputs , y = ...` 是"最后一个元素是标签、其余全是输入"的通用解包（`*` 在赋值处**收集**，在 `self.model(*inputs)` 处**展开**，一收一放）；`zero_grad → backward → step` 的顺序不可颠倒；`running` 先乘 `y.size(0)` 再累加、最后除以 `n`，得到的是**按样本加权的平均损失**——如果只累加 `loss.item()` 却除以样本数，train_loss 会被缩小 `batch_size` 倍（第三部分坑 4 实测比值 0.0591 ≈ 1/16）。两个循环里的指标都乘 `x.size(0)`，是为了让 train / dev 口径一致、最后一批不满时也不偏袒小 batch。

# 三、踩坑记录

低级错误小表格：

| 错误 | 修正 |
|---|---|
| 没留 test 集（105 + 45 = 150 全用完） | 重新划分 7:2:1 或交叉验证 |
| `history` 声明了 `Train_score` 但从未写入 | `train()` 里补 `running_score` 统计 |
| `evaluate` 没加 `@torch.no_grad()` | 加装饰器 |
| 归一化用全局标量 `X_train.mean()` | 按特征：`X_train.mean(0)` / `std(0)` |
| `print(runner.history['Dev_score'])` 吐出 500 个数 | 打印 `min` / `argmin`，或直接看曲线 |

中级错误：

**1. 划分前未应用随机排列**

错误代码：

```python
perm = torch.randperm(len(X))
tr = int(len(X) * 0.7)
X_train = X[:tr]          # perm 计算后未使用
X_dev = X[tr:]
```

`load_iris` 返回的标签按类别排序（50 / 50 / 50）。直接顺序切片后，训练集包含 `[50, 50, 5]` 条，验证集 45 条全部为 virginica。此时 `Dev_score` 恒为 0.0，而 `Dev_loss` 仍在正常波动，现象上容易误判为模型或损失函数的问题。需要注意 `DataLoader(shuffle=True)` 仅打乱 batch 内部顺序，无法修正划分阶段的错误。

修正代码：

```python
perm = torch.randperm(len(X))
X, y = X[perm], y[perm]   # 先打乱，再切片
X_train = X[:tr]
X_dev = X[tr:]
```

**2. `forward` 返回中间激活而非 logits**

错误代码：

```python
def forward(self, inputs):
    z1 = self.fc1(inputs)
    a1 = self.ac(z1)
    z2 = self.fc2(a1)
    return a1              # 应返回 z2
```

`nn.CrossEntropyLoss` 仅要求输入第 0 维长度与标签长度一致，因此 16 维的隐藏层激活配 0..2 的标签在语法上完全合法，损失函数会将其视为 16 分类的 logits 进行计算，不产生任何报错。更严重的是，`fc2` 的输出未参与最终返回值的计算图，实测 `model.fc2.weight.grad is None`，训练前后 `fc2` 权重变化量为 0.0，即输出层始终保持随机初始化状态，实际参与训练的只有 `fc1`。两种廉价的自检手段：打印 `model(x).shape` 确认最后一维等于类别数；`loss.backward()` 之后遍历 `model.parameters()`，检查是否存在 `p.grad is None` 的参数。

修正代码：

```python
def forward(self, inputs):
    z1 = self.fc1(inputs)
    a1 = self.ac(z1)
    z2 = self.fc2(a1)
    return z2
```

**3. 训练损失累加与平均的口径不一致**

错误代码：

```python
running += loss.item()    # 累加的是每个 batch 的平均损失
# ...
train_loss = running / n  # 分母却是样本总数
```

`loss.item()` 返回的是当前 batch 的平均损失，将其直接累加后再除以样本总数 `n`，相当于把 train_loss 缩小了 batch_size 倍（实测 train_loss 与 dev_loss 的比值为 0.0591 ≈ 1/16）。此外，按 batch 求简单平均时，最后一个不满的 batch 会获得与满 batch 相同的权重，导致 train 与 dev 两侧的统计口径不一致。

修正代码：

```python
running += loss.item() * y.size(0)   # 按样本数加权累加
# ...
train_loss = running / n             # 再除以样本总数
```

# 四、过拟合

训练后期 `Train_loss` 持续下降而 `Dev_loss` 回升，曲线呈 U 形。参数量 131 > 训练样本 105，属于典型的容量过剩过拟合。12 组对照实验（隐藏层 16、batch 16、Adam，只改学习率、轮数、种子）：

| 学习率 | 轮数 | 种子 0 | 种子 1 | 种子 2 | 末轮 train_loss |
|---|---|---|---|---|---|
| 0.003 | 200 | +0.0000 | +0.0000 | +0.0015 | 0.079 – 0.117 |
| 0.003 | 1000 | +0.0064 | +0.0000 | +0.0754 | 0.013 – 0.063 |
| 0.1 | 200 | +0.0129 | +0.0413 | +0.1878 | 0.006 – 0.053 |
| 0.1 | 1000 | +0.2582 | +0.3072 | **+0.8416** | **0.0000 – 0.027** |
（dev_loss − best dev_loss）

学习率越大、轮数越多，回升越严重。lr=0.1 / 1000 轮时 train_loss 压到 0.0000，模型已完全记住训练集。另外 dev_loss 比 dev_acc 更敏感：某次 dev_acc 仅从 0.956 掉到 0.933，dev_loss 却涨了 0.33，看 loss 能更早发现过拟合。

解决：1、加 best-checkpoint（`deepcopy` 跟踪 dev_loss 最小的快照，训练结束回载）；2、轮数降到 200 以内；3、加 `weight_decay`（1e-4）或 `nn.Dropout` ；4、固定划分种子并按类别分层。

# 五、与上一次练习的对照

第一部分手写链式法则，核心是新东西是算子局部反向规则和逆序调用链。这一部分把求导外包给框架，核心新东西变成了边界意识：autograd 只负责"给定标量 loss 把梯度算出来"，零梯度、反向顺序、参数更新、batch 划分、加权平均、指标口径全是自己的事——8 个坑里 6 个落在框架不管的地方。

softmax + CE 的合成梯度（预测减标签）之所以干净，是因为框架把逐元素门和链式法则藏起来了。不先手推一遍，就没法判断框架算的对不对。

第一部分纠结的是初始化和学习率让 GD 走得动（欠优化）；这一部分 Adam 让它轻松走到 `train_loss = 0`，问题反转成过拟合与早停——优化太好，反而暴露了泛化问题。

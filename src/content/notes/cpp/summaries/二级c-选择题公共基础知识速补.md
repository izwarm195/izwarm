# 一、数据结构与算法

## 1.1 算法的基本概念

**必背结论**

- 算法是**解题方案的准确而完整的描述**，是指令的有限序列；**算法 ≠ 程序**，算法 ≠ 计算方法。
- 算法的四个基本特性：**可行性、确定性、有穷性、拥有足够的情报**。
  - 可行性：每一步都能用基本运算执行有限次实现。
  - 确定性：每一步有明确定义，无歧义（这是算法与数学公式的明显区别）。
  - 有穷性：必须在有限时间内、执行有限步骤后终止。
  - 拥有足够的情报：可有多个输入或没有输入，但**必须有输出**。
- **时间复杂度 = 执行算法所需的基本运算（计算工作量）次数**；**空间复杂度 = 执行算法所需的内存（存储）空间**。两者都只看问题规模 n 的量级，与机器无关。

> <img class="callout-badge" src="/media/icons/triangle-exclaimation.svg" alt="warning">**易错**
> - "算法就是程序" ❌（程序可以死循环、可以不满足有穷性）。
> - 时间复杂度**不是**"算法执行的具体时间""语句条数""处理的数据量"；空间复杂度**不是**"临时工作单元数"。
> - 空间复杂度问的是**整个算法执行过程中需要的计算机存储空间**，不要只盯"临时工作单元"。

**例题**

> **【2015年3月·2】** 算法的时间复杂度是指 ___。
> A）算法的执行时间　B）算法所处理的数据量　C）算法程序中的语句或指令条数　D）算法在执行过程中所需要的基本（运算次数）
> **答案：D**。时间复杂度指算法执行过程中所需要的基本运算次数，是随规模增长的数量级。

> **【2014年9月·4】** 算法的空间复杂度是指 ___。
> A）算法在执行过程中所需要的计算机存储空间　B）算法所处理的数据量　C）算法程序中的语句或指令条数　D）算法在执行过程中所需要的临时工作单元数
> **答案：A**。

> **【2011年9月·1】** 下列叙述中正确的是 ___。
> A）算法就是程序　B）设计算法时只需要考虑数据结构的设计　C）设计算法时只需要考虑结果的可靠性　D）以上三种说法都不对
> **答案：D**。设计算法要考虑可行性、确定性、有穷性和拥有足够的情报。

## 1.2 逻辑结构与存储结构

**必背结论**

- **四类基本逻辑结构**（按数据元素间关系划分）：
  1. **集合结构**：元素间仅"属于同一集合"，关系最松散。
  2. **线性结构**：元素之间**一对一**。
  3. **树形结构**：元素之间**一对多**。
  4. **图形（网状）结构**：元素之间**多对多**。
- **存储结构（物理结构）**：
  - **顺序存储**：逻辑相邻→物理位置相邻，通常用数组实现。
  - **链式存储**：不要求物理相邻，靠**指针字段**表示逻辑关系。
  - 另有**索引存储**与**散列存储**（为便于查找）。
- 图形表示：数据元素用方框（结点）表示，二元组用**有向线段**从前件结点指向后件结点。

  **例题**

> **【2013年9月·4】** 下列叙述中正确的是 ___。
> A）顺序存储结构的存储一定是连续的，链式存储结构的存储空间不一定是连续的
> B）顺序存储结构只针对线性结构，链式存储结构只针对非线性结构
> C）顺序存储结构能存储有序表，链式存储结构不能存储有序表
> D）链式存储结构比顺序存储结构节省存储空间
> **答案：A**。存储结构（顺序/链式）与逻辑结构（线性/非线性）是两回事：链式也能存线性结构，顺序也能存二叉树。

## 1.3 线性结构的判定（几乎年年出）

**判定口诀**：线性结构 = **有且仅有一个根结点** + **每个结点最多一个前件、最多一个后件**。

| 属于线性结构 | 属于非线性结构 |
|---|---|
| 线性表（含有序线性表）、栈、队列、循环队列 | 二叉树、二叉链表、树 |
| 循环链表、双向链表、带链的栈、带链的队列 | 图、网状结构 |

> <img class="callout-badge" src="/media/icons/triangle-exclaimation.svg" alt="warning">**易错**
> - **循环队列有两个指针，但仍是线性结构**（且是顺序存储）——"循环队列是非线性结构"永远错。
> - **双向链表每个结点有两个指针，仍是线性结构**——判断看逻辑关系，不看指针个数。
> - "只有一个根结点的数据结构**不一定**是线性结构" ✔（如只有一个根、但有结点有两个后件）。
> - "有一个以上根结点的数据结构**一定是**非线性结构" ✔。

**例题**

> **【2014年9月·1】** 下列数据结构中，属于非线性结构的是 ___。
> A）循环队列　B）带链队列　C）二叉树　D）带链栈
> **答案：C**。二叉树中结点可以有两个后件，不满足线性结构条件。

> **【2013年3月·1】** 下列数据结构中，属于非线性结构的是 ___。
> A）双向链表　B）循环链表　C）二叉链表　D）循环队列
> **答案：C**。二叉链表是二叉树的存储结构。

> **【2012年9月·1】** 下列链表中，其逻辑结构属于非线性结构的是 ___。
> A）二叉链表　B）循环链表　C）双向链表　D）带链的栈
> **答案：A**。

> **【2011年3月·2】** 下列叙述中正确的是 ___。
> A）有一个以上根结点的数据结构不一定是非线性结构　B）只有一个根结点的数据结构不一定是线性结构　C）循环链表是非线性结构　D）双向链表是非线性结构
> **答案：B**。

> **【2014年3月·1】** 下列叙述中正确的是 ___。
> A）栈是"先进先出"的线性表　B）队列是"先进后出"的线性表　C）循环队列是非线性结构　D）有序线性表既可以采用顺序（存储结构，也可以采用链式存储结构）
> **答案：D**。

## 1.4 顺序存储 vs 链式存储

| 比较项 | 顺序存储 | 链式存储 |
|---|---|---|
| 存储空间 | 必须连续 | 可以不连续 |
| 额外开销 | 无 | 每个结点要有指针域，**一般比顺序多占空间** |
| 插入/删除 | 需要移动大量元素 | **只改指针，不移动元素** |
| 访问方式 | 可随机存取（下标） | 只能从头指针顺序访问 |
| 能否二分查找 | 可以（有序时） | **不可以** |

**例题**

> **【2015年9月·1】** 下列叙述中正确的是 ___。
> A）线性表的链式存储结构与顺序存储结构所需要的存储空间是相同的
> B）线性表的链式存储结构所需要的存储空间一般要多于顺序存储结构
> C）线性表的链式存储结构所需要的存储空间一般要少于顺序存储结构
> D）上述三种说法都不对
> **答案：B**。链式除了存数据，还要存指向下一个元素的指针。

> **【2011年9月·2】** 下列线性链表的叙述中，正确的是 ___。
> A）各数据结点的存储空间可以不连续，但它们的存储顺序与逻辑顺序必须一致
> B）各数据结点的存储顺序与逻辑顺序可以不一致，但它们的存储空间必须连续
> C）进行插入与删除时，不需要移动表中的元素
> D）以上三种说法都不对
> **答案：C**。

> **【2013年3月·2】** 在下列链表中，能够从任意一个结点出发直接访问到所有结点的是 ___。
> A）单链表　B）循环链表　C）双向链表　D）二叉链表
> **答案：B**。循环链表尾结点指针指回表头，构成环状链。

## 1.5 栈（LIFO）

**必背结论**

- 栈是**只允许在一端（栈顶）进行插入和删除**的线性表，是**操作受限的线性表**。
- 原则：**后进先出 LIFO**；栈底指针**不变**，元素随**栈顶指针**变化。
- 栈顶元素**最先**能被删除/出栈；栈底元素最先入栈、最后出栈。
- 典型应用：**函数（子程序）调用、递归调用**、表达式求值、括号匹配。

  **例题**

> **【2015年9月·2】** 下列叙述中正确的是 ___。
> A）在栈中，栈中元素随栈底指针与栈顶指针的变化而动态变化
> B）在栈中，栈顶指针不变，栈中元素随栈底指针的变化而动态变化
> C）在栈中，栈底指针不变，栈中元素随栈顶指针的变化而动态变化
> D）上述三种说法都不对
> **答案：C**。

> **【2011年3月·1】** 下列关于栈叙述正确的是 ___。
> A）栈顶元素最先能被删除　B）栈顶元素最后才能被删除　C）栈底元素永远不能被删除　D）以上三种说法都不对
> **答案：A**。

> **【2012年9月·3】** 下列关于栈的叙述中，正确的是 ___。
> A）栈底元素一定是最后入栈的元素　B）栈顶元素一定是最先入栈的元素　C）栈操作遵循先进后出的原则　D）以上三种说法都不对
> **答案：C**。最先入栈的在栈底、最后出栈；最后入栈的在栈顶、最先出栈。

> **【2014年3月·2】** 支持子程序调用的数据结构是 ___。
> A）栈　B）树　C）队列　D）二叉树
> **答案：A**。函数调用时局部变量、参数、返回地址都存在栈里的"活动记录（栈帧）"中。

> **【2013年3月·3】** 下列与栈结构有关联的是 ___。
> A）数组的定义域使用　B）操作系统的进程调度　C）函数的递归调用　D）选择结构的执行
> **答案：C**。

> **【2013年9月·1】** 一个栈的初始状态为空。现将元素 1、2、3、4、5、A、B、C、D、E 依次入栈，然后再依次出栈，则元素出栈的顺序是 ___。
> A）12345ABCDE　B）EDCBA54321　C）ABCDE12345　D）54321EDCBA
> **答案：D**。全部入栈后再出栈，出口顺序必然与入栈顺序完全相反。

## 1.6 队列与循环队列（FIFO）

**必背结论**

- 队列：**队尾插入、队头删除**的线性表，**先进先出 FIFO**。
- **循环队列是队列的一种顺序存储结构**，仍是线性结构，只是把顺序空间首尾相接。
- **循环队列元素个数由队头指针 front 和队尾指针 rear 共同决定**：
  $$
  n = (\text{rear} - \text{front} + m) \bmod m \quad (m\ \text{为存储空间大小})
  $$
- 队头指针**可以大于也可以小于**队尾指针（绕回时 front > rear）。
- `front = rear` 时通常是**队空**；但若"少用一个存储单元"的约定下也可能表示**队满**——这正是真题里"D）0 或 35"的由来。

  **例题**

> **【2012年3月·1】** 下列叙述中正确的是 ___。
> A）循环队列是队列的一种链式存储结构　B）循环队列是一种逻辑结构　C）循环队列是队列的一种顺序存储结构　D）循环队列是非线性结构
> **答案：C**。

> **【2013年9月·2】** 下列叙述中正确的是 ___。
> A）循环队列有队头和队尾两个指针，因此，循环队列是非线性结构
> B）在循环队列中，只需要队头指针就能反映队列中元素的动态变化情况
> C）在循环队列中，只需要队尾指针就能反映队列中元素的动态变化情况
> D）循环队列中元素的个数是由队头指针和队尾指针共同决定
> **答案：D**。

> **【2014年9月·3】** 对于循环队列，下列叙述中正确的是 ___。
> A）队头指针是固定不变的　B）队头指针一定大于队尾指针　C）队头指针一定小于队尾指针　D）队头指针可以大于队尾指针，也可以小于队尾指针
> **答案：D**。

> **【2012年9月·2】** 设循环队列的存储空间为 Q(1:35)，初始状态为 front=rear=35。现经过一系列入队与退队运算后，front=15，rear=15，则循环队列的元素个数为 ___。
> A）15　B）16　C）20　D）0 或 35
> **答案：D**。front=rear 时为队空（0 个），在"牺牲一个单元判满"的约定下也可能表示队满（35 个）。

## 1.7 树与二叉树（第 3、4 题的高频区）

**必背结论**

- **树**：非线性结构，n≥0 个结点的有限集；n≠0 时**有且仅有一个根结点**，其余结点分成 m 个互不相交的子树。树中**每个结点的度可以是任意的**。
- **二叉树**：非线性结构；**每个结点最多有两棵子树**（左子树、右子树），**度最大为 2**；可以是空二叉树。
- **必背性质**：
  1. 第 k 层最多有 $2^{k-1}$ 个结点。
  2. 深度为 m 的二叉树最多有 $2^m - 1$ 个结点。
  3. **叶子结点数 $n_0$ = 度为 2 的结点数 $n_2$ + 1**（年年考，务必记牢）。
  4. 结点总数 $n = n_0 + n_1 + n_2$（$n_1$ 为度为 1 的结点数）。
  5. **深度 = 最大层次**（根结点在第 1 层）。完全二叉树 n 个结点的深度为 $\lfloor \log_2 n \rfloor + 1$。
- 存储结构：**二叉链表**（链式）、顺序存储。

  **解题套路（三招）**

1. 给 $n_2$ 求 $n_0$：$n_0 = n_2 + 1$。
2. 给 $n$ 和 $n_0$ 求 $n_1$：由 $n = n_0 + n_1 + n_2$ 且 $n_2 = n_0 - 1$ 得 $n_1 = n - 2n_0 + 1$。
3. 给"只有 1 个叶子"求最大深度：这种二叉树每一层最多 1 个叶子，其余结点度为 1，即**退化成一条链**，深度 = 结点数。

  **例题**

> **【2011年9月·3】** 下列关于二叉树的叙述中，正确的是 ___。
> A）叶子结点总是比度为 2 的结点少一个　B）叶子结点总是比度为 2 的结点多一个　C）叶子结点数是度为 2 的结点数的两倍　D）度为 2 的结点数是度为 1 的结点数的两倍
> **答案：B**。

> **【2014年3月·3】** 某二叉树有 5 个度为 2 的结点，则该二叉树中的叶子结点数是 ___。
> A）10　B）8　C）6　D）4
> **答案：C**。$n_0 = n_2 + 1 = 5 + 1 = 6$。

> **【2012年3月·3】** 一棵二叉树共有 25 个结点，其中 5 个是叶子结点，则度为 1 的结点数为 ___。
> A）16　B）10　C）6　D）4
> **答案：A**。$n_2 = n_0 - 1 = 4$，$n_1 = 25 - 5 - 4 = 16$。

> **【2011年3月·3】** 某二叉树共有 7 个结点，其中叶子结点只有 1 个，则该二叉树的深度为（假设根结点在第 1 层）___。
> A）3　B）4　C）6　D）7
> **答案：D**。只有 1 个叶子时树退化成单链，7 个结点即 7 层。

> **【2011年9月·5】** 某系统总体结构图（树形）如题图所示，该系统总体结构图的深度是 ___。
> A）7　B）6　C）3　D）2
> **答案：C**。**树的最大层次就是树的深度**，图中共 3 层。

## 1.8 查找

| 方法 | 适用前提 | 最坏比较次数 | 结论 |
|---|---|---|---|
| 顺序查找 | 顺序表或链表 | **n 次** | **链表只能用顺序查找** |
| 二分（对分）查找 | **顺序存储 + 有序** | $O(\log_2 n)$（约 $\log_2 n$ 次） | 链表不能二分 |

> <img class="callout-badge" src="/media/icons/triangle-exclaimation.svg" alt="warning">**易错**
> "对长度为 n 的**有序链表**进行**对分查找**"是**错的命题**——链表无法按下标折半定位。

**例题**

> **【2015年3月·1】** 下列叙述中正确的是 ___。
> A）对长度为 n 的有序链表进行查找，最坏情况下需要的比较次数为 n
> B）对长度为 n 的有序链表进行对分查找，最坏情况下需要的比较次数为 (n/2)
> C）对长度为 n 的有序链表进行对分查找，最坏情况下需要的比较次数为 (log₂n)
> D）对长度为 n 的有序链表进行对分查找，最坏情况下需要的比较次数为 (n·log₂n)
> **答案：A**。链表只能顺序查找，最坏比较 n 次。

> **【2013年9月·3】** 在长度为 n 的有序**线性表**中进行二分查找，最坏情况下需要比较的次数是 ___。
> A）O(n)　B）O(n²)　C）O(log₂n)　D）O(n·log₂n)
> **答案：C**。

## 1.9 排序

| 排序方法 | 平均时间 | 最坏时间 | 空间 | 稳定性 |
|---|---|---|---|---|
| 冒泡排序 | O(n²) | O(n²) | O(1) | **稳定** |
| 直接插入排序 | O(n²) | O(n²)，比较/移动 n(n−1)/2 | O(1) | **稳定** |
| 简单选择排序 | O(n²) | O(n²) | O(1) | 不稳定 |
| 希尔排序 | O(n^1.3) | — | O(1) | 不稳定 |
| **快速排序** | **O(n·log₂n)（同数量级中平均性能最好）** | **O(n²)**（初始有序时退化为冒泡） | O(log₂n) | 不稳定 |
| **堆排序** | O(n·log₂n) | **O(n·log₂n)（最坏情况比较次数最少）** | O(1) | 不稳定 |
| 归并排序 | O(n·log₂n) | O(n·log₂n) | O(n) | **稳定** |

**必背三条**

- 问"**最坏情况下比较次数最少**"→ 选 **堆排序**。
- 问"**平均时间效率最好**"→ 选 **快速排序**；但**初始基本有序时快排最慢**（退化为冒泡）。
- 稳定排序记忆：**冒泡、插入、归并稳定**；**快排、希尔、堆、选择不稳定**。

  **例题**

> **【2014年3月·4】** 下列排序方法中，最坏情况下比较次数最少的是 ___。
> A）冒泡排序　B）简单选择排序　C）直接插入排序　D）堆排序
> **答案：D**。前三者最坏均为 O(n²)，堆排序为 O(n·log₂n)。

## 1.10 数据结构部分速记表

| 考点 | 一句话结论 |
|---|---|
| 时间复杂度 | 基本运算次数 |
| 空间复杂度 | 所需存储空间 |
| 线性结构 | 一个根 + 每点最多一前一后 |
| 循环队列 | 线性结构、顺序存储；元素个数 =(rear−front+m) mod m |
| 栈 | LIFO；栈底不动；支持函数调用与递归 |
| 队列 | FIFO；队头出、队尾进 |
| 二叉树 | 度 ≤ 2；$n_0 = n_2 + 1$；$n = n_0+n_1+n_2$ |
| 深度 | 最大层次 |
| 顺序 vs 链式 | 链式多花指针空间、插入删除不移动元素 |
| 二分查找 | 必须顺序存储且有序，O(log₂n) |
| 最坏最优排序 | 堆排序；平均最优是快排 |

# 二、程序设计基础

## 2.1 结构化程序设计

**必背结论**

- **三种基本结构**：**顺序结构、选择（分支）结构、循环（重复）结构**。三种结构足以表达任意算法功能。
- **四条基本原则**：**自顶向下、逐步求精、模块化、限制使用 goto 语句**。
  - 自顶向下：先考虑总体、后考虑细节。
  - 逐步求精：复杂问题设计中间目标，逐步细化。
  - 模块化：把总目标分解为多个小目标，每个小目标是一个模块。
- **模块独立性**由两个指标衡量：
  - **内聚性**：一个模块**内部**各元素彼此结合的紧密程度 → **越强越好**。
  - **耦合性**：**模块之间**互相连接的紧密程度 → **越弱越好**。
  - 目标：**高内聚、低耦合**（这是历年必考句）。

> <img class="callout-badge" src="/media/icons/triangle-exclaimation.svg" alt="warning">**易错**
> - "可封装""继承""多态"是**面向对象**的概念，不属于结构化程序设计原则（经典干扰项）。
> - **内聚看模块内部，耦合看模块之间**——两个定义常被互换来设错。
> - goto 语句是"**限制**使用"而不是"完全禁止"。

**例题**

> **答案：A**。

> **【2011年3月·5】** 结构化程序所要求的基本结构不包括 ___。
> A）顺序结构　B）GOTO 跳转　C）选择（分支）结构　D）重复（循环）结构
> **答案：B**。

> **【2014年3月·7】** 耦合性和内聚性是对模块独立性度量的两个标准。下列叙述中正确的是 ___。
> A）提高耦合性降低内聚性有利于提高模块的独立性
> B）降低耦合性提高内聚性有利于提高模块的独立性
> C）耦合性是指一个模块内部各个元素间彼此结合的紧密程度
> D）内聚性是指模块间互相连接的紧密程度
> **答案：B**。

> A）低内聚低耦合　B）高内聚低耦合　C）低内聚高耦合　D）高内聚高耦合
> **答案：B**。

## 2.2 面向对象方法

**必背结论**

- **对象的基本特点**：**标识唯一性、分类性、多态性、继承性**（部分教材加"封装性"）。
  - 干扰项常用"**一致性**""共享性"等杜撰词——"一致性"不属于对象的基本特点。
- **继承**：**类之间共享属性和操作的机制**（新类从已有类获得已有特性）。
- **面向对象方法的主要特征**：**封装、继承、多态**。
- "封装""继承""多态"三个词出现时，选项基本都在考"这是面向对象而非结构化"。

  **例题**

> **答案：D**。

> **答案：A**。

## 2.3 程序设计风格

**必背结论**

- 主导思想：**"清晰第一，效率第二"**。
- 良好风格主要考虑四个方面：**源程序文档化、数据说明、语句结构、输入输出**。
- 作用：使程序结构清晰合理、便于阅读和维护、提高开发效率。

# 三、软件工程基础

## 3.1 软件、软件危机、软件生命周期

**必背结论**

- 软件按功能分三类：
  - **应用软件**：解决特定领域实际问题，如**教务管理系统、学生成绩管理系统**、文字处理、表格处理、Photoshop。
  - **系统软件**：管理和控制计算机软硬件资源，核心是**操作系统**，还包括语言处理程序、服务性程序、**数据库管理系统**。
  - **支撑软件（工具软件）**：协助开发的工具，如需求分析工具、设计工具、编码工具、测试工具。
  > <img class="callout-badge" src="/media/icons/triangle-exclaimation.svg" alt="warning">**教材口径提醒**
  > 本书 2014年3月卷解析把"**编译程序、汇编程序**"归入**支撑软件**，而 2013年3月卷解析把"各种语言的解释程序和编译程序"列入**系统软件**。遇到这类选项时，优先按"**操作系统=系统软件**""**教务/学生管理系统=应用软件**""**编译/汇编程序/开发工具=支撑软件**"来排除，避开有争议项。
- 软件危机的表现：**成本无法控制、质量难以保证、生产率提高慢、不可维护、需求增长得不到满足**。总结为**成本、质量、生产率**问题。
  - 干扰项"**软件过程不规范**"不属于软件危机表现。
- 软件的特点：**逻辑实体、具有抽象性**；开发运行**依赖计算机系统**；涉及**知识产权、法律、心理等社会因素**；**不存在磨损和老化问题**（这句几乎年年设错）。
- **软件生命周期**：软件产品从**提出、实现、使用维护到停止使用退役**的整个过程。
  - 三阶段划分：**定义阶段**（可行性研究、需求分析）→ **开发阶段**（概要设计、详细设计、编码、测试）→ **维护阶段**（使用、维护、退役）。
  - **详细设计属于开发阶段**。
  - "**市场调研**"不属于软件生命周期的活动。

## 3.2 需求分析（工具辨析是重灾区）

**必背结论**

- 需求分析的任务：**确定功能需求、性能需求、数据需求**，编写**软件需求规格说明书（SRS）**并评审。
- **结构化分析（SA）的常用工具**：**数据流图 DFD、数据字典 DD、结构化英语、判定表、判定树**。
  - **DFD 是"结构化方法的需求分析工具"**（不是设计工具、不是面向对象工具）。
  - DFD 中**带箭头的线段表示数据流**；基本图符还有加工（方框/圆）、数据存储、外部实体。
  - **DD（数据字典）的四类条目：数据流、数据项、数据存储、加工**；DD 的作用是**对 DFD 中出现的被命名的图形元素给出确切解释**；DD 在**需求分析阶段**建立，之后不断修改充实。
- **SRS 的作用**：便于开发人员理解交流、反映用户问题的结构、作为**软件开发的基础和依据**、作为**确认测试和验收的依据**。
  - **SRS 不能作为"可行性研究的依据"**（可行性研究在需求分析**之前**）。
- 需求分析阶段**不**制订集成/确认测试计划（这属于设计阶段的任务）。

## 3.3 软件设计

**必背结论**

- 软件设计 = **把软件需求转换为软件表示的过程**；分**概要设计（总体设计）**与**详细设计**。
- **概要设计的任务**：软件系统的**结构设计**（模块划分、调用关系）、**数据结构与数据库设计**、接口设计、编写概要设计文档并评审。
  - **软件的功能确定属于需求分析**，不属于设计阶段。
- **详细设计的任务**：过程（算法）设计；**表示工具：程序流程图、N-S 图、PAD 图、判定表**。
- **系统结构图（SC）**：反映系统中**模块的调用关系和层次关系**，是**总体（概要）设计**的表示工具，**不支持详细设计**。
- **模块独立性**：内聚 + 耦合两个指标（见 2.1）。

## 3.4 软件测试

**必背结论**

- **测试的目的：尽可能多地发现程序中的错误**（"发现并改正错误"是错的——改正是调试的任务；"验证程序正确性"也错）。
- 测试贯穿软件开发全过程（对比：调试在测试之后）。
- 分类：
  - 按**是否执行被测程序**：**静态测试**（分析文档/代码，不运行）与**动态测试**（运行程序）。
  - 按**功能**：**白盒测试**（依据**程序内部逻辑**，又称结构测试）与**黑盒测试**（依据**程序外部功能**，不考虑内部结构）。
- **白盒方法**：**语句覆盖、判定/逻辑覆盖、路径分析、基本路径测试**。
- **黑盒方法**：**等价类划分、边界值分析、错误推测法、因果图**。
- 软件测试的步骤：**单元测试 → 集成测试 → 确认测试 → 系统测试**。

> <img class="callout-badge" src="/media/icons/lightbulb.svg" alt="tip">**一句话判别**
> 看到"**覆盖/路径**"→ 白盒；看到"**等价类/边界值/因果图/外部功能**"→ 黑盒。

## 3.5 程序调试（Debug）

**必背结论**

- **调试的任务：诊断并改正程序中的错误**（测试只负责"发现"）。
- **调试步骤：① 错误定位 → ② 修改代码 → ③ 回归测试**。
- 调试分**静态调试**（靠人的思维分析源程序，**主要手段**）与**动态调试**（借助工具跟踪执行，**辅助手段**）。
- "错误定位是程序调试的必要步骤" ✔；"程序调试通常也称为 Debug" ✔。

  **测试 vs 调试 对照表**

  | 比较项 | 软件测试 | 程序调试 |
  |---|---|---|
  | 目的 | **尽可能多地发现错误** | **诊断并改正错误** |
  | 是否改正 | 不改正 | 改正 |
  | 时机 | 贯穿开发全过程 | 测试之后 |
  | 能否发现全部错误 | 不能 | 也不能保证 |

  **例题**

> **【2014年3月·6】** 下面叙述中错误的是 ___。
> A）软件测试的目的是发现错误并改正错误　B）对被调试的程序进行"错误定位"是程序调试的必要步骤　C）程序调试通常也称为 Debug　D）软件测试应严格执行测试计划，排除测试的随意性
> **答案：A**。

> **【2015年3月·4】** 软件（程序）调试的任务是 ___。
> A）诊断和改正程序中的错误　B）尽可能多地发现程序中的错误　C）发现并改正程序中的所有错误　D）确定程序中错误的性质
> **答案：A**。

> **【2011年9月·6】** 程序调试的任务是 ___。
> A）设计测试用例　B）验证程序的正确性　C）发现程序中的错误　D）诊断和改正程序中的错误
> **答案：D**。

## 3.6 软件工程"工具 / 文档 — 阶段"速查表

| 阶段 | 主要任务 | 常用工具 / 产物 |
|---|---|---|
| 可行性研究 | 技术、经济、操作可行性 | 可行性研究报告 |

> <img class="callout-badge" src="/media/icons/triangle-exclaimation.svg" alt="warning">**最常见的三个陷阱**

# 四、数据库设计基础

## 4.1 基本概念与数据库语言

**必背结论**

- **数据库（DB）**：长期存储在计算机内、有组织、可共享的数据集合。
- **数据库管理系统（DBMS）**：一种**系统软件**（在**操作系统支持下**运行），负责数据组织、操纵、维护、控制、保护与服务；主要功能是数据定义、数据操纵、数据库运行管理、建库与维护。
- **数据管理技术三阶段**：**人工管理 → 文件系统 → 数据库系统**；**数据共享最好的是数据库系统阶段**（人工管理阶段数据不保存、不共享）。
- **数据库语言三部分**：
  | 语言 | 职责 |
  |---|---|
  | **DDL** 数据定义语言 | 负责数据的**模式定义**与**物理存取构建** |
  | **DML** 数据操纵语言 | 负责**查询**及增、删、改等基本操作 |
  | **DCL** 数据控制语言 | 负责**完整性、安全性的定义与检查**，并发控制、故障恢复 |
- 数据库语言有两种结构形式：**交互式命令语言**（终端即时操作）与**宿主型语言**（嵌入 C/C++ 等宿主语言）。
- 目前主流 DBMS 都是**关系型**（Oracle、Sybase 等）。

## 4.2 数据模型

**必背结论**

- **数据模型三要素**：**数据结构、数据操作、数据完整性约束**。
  - 数据结构是基础；数据约束是完整性规则的集合。
- **按应用层次分三类**：
  1. **概念数据模型**：面向客观世界、面向用户，**与具体 DBMS 和计算机平台无关**，典型代表 **E-R 模型**。
  2. **逻辑数据模型**（常简称数据模型）：面向数据库系统，如**层次模型、网状模型、关系模型**。
  3. **物理数据模型**：面向计算机物理表示。
- **层次型 / 网状型 / 关系型数据库的划分原则 = 数据之间的联系方式**（不是记录长度、文件大小、联系复杂程度）。

  **例题**

> **【2015年9月·7】** 层次型、网状型和关系型数据库划分原则是 ___。
> A）记录长度　B）文件的大小　C）联系的复杂程度　D）数据之间的联系方式
> **答案：D**。

## 4.3 三级模式与数据独立性

**必背结论**

- **数据库系统的三级模式**（**不包括"数据模式"**这种说法）：
- 
  | 模式 | 含义 | 记忆点 |
  |---|---|---|
  | **概念模式**（模式/逻辑模式） | 对**全局数据逻辑结构**的描述 | 全体数据的逻辑视图 |
  | **外模式**（子模式/用户模式） | **用户的数据视图**，反映**用户对数据的要求** | 一库可有多个外模式 |
  | **内模式**（物理模式/存储模式） | 给出**物理存储结构与物理存取方法** | **对用户透明** |
- **数据独立性**：程序与数据互相独立，分两级：
  - **物理独立性**：物理结构（存储设备、存取方式）改变不影响逻辑结构，也不影响应用程序。
  - **逻辑独立性**：总体逻辑结构（修改数据模式、增加数据类型、改变数据联系）改变**不需要修改应用程序**。

    **例题**

> **【2015年9月·9】** 数据库设计中反映用户对数据要求的模式是 ___。
> A）内模式　B）概念模式　C）外模式　D）设计模式
> **答案：C**。

> A）外模式　B）内模式　C）概念模式　D）逻辑模式
> **答案：B**。

> **【2011年9月·8】** 数据库系统的三级模式不包括 ___。
> A）概念模式　B）内模式　C）外模式　D）数据模式
> **答案：D**。

## 4.4 E-R 模型（概念模型）

**必背结论**

- E-R 图（实体-联系图）用于描述**现实世界的概念模型**，是**概念设计阶段**的工具，**不涉及信息在计算机中的表示**。
- **图形符号（必背）**：

  | 符号 | 表示 |
  |---|---|
  | **矩形** | **实体**（实体集） |
  | **椭圆（椭圆形）** | **属性** |
  | **菱形** | **联系** |

- **实体之间的联系类型**：**一对一 1:1、一对多 1:m、多对多 m:n**。
  - **没有"多对一 m:1"这种联系类型**（见到 m:1 直接排除）。
  - 判别技巧：把两边的数量都说成"多个"→ m:n；"A 可有多个 B，但 B 只属于一个 A"→ A 对 B 是 1:m。
- **E-R 图设计属于数据库设计的"概念设计阶段"**；把 **E-R 图转换成关系模式属于"逻辑设计阶段"**；转换时**实体和联系都可以表示为关系**。

## 4.5 关系模型与关键字（"关键字"高频考点）

**必背结论**

- **关系数据库用二维表来表示实体间的联系**。
- 术语对照：

  | 关系术语 | 通俗说法 |
  |---|---|
  | 关系 | 一张**二维表** |
  | 元组 | 表中的**一行** |
  | 属性 | 表中的**一列** |
  | 域 | 属性的**取值范围** |
  | 分量 | 元组中的一个属性值 |
- **键（关键字）体系（必背）**：

  | 名称 | 定义 |
  |---|---|
  | **超键** | 能唯一标识元组的属性集合 |
  | **候选关键字（候选键）** | 不含多余属性的超键，**能唯一标识元组** |
  | **主关键字（主键）** | 从候选键中选定的一个 |
  | **外关键字（外键）** | 本关系中引用其他关系主键的属性 |
- **实体完整性约束**：关系的**主属性（主键）不能取空值**；由此要求**一个关系中应该有一个或多个候选关键字**（"只能有一个"❌、"可以没有"❌）。
- **能作为关键字的属性必须能唯一区分每条记录**。如图书属性 {ISBN 书号，书名，作者，出版社，出版日期} 中，**ISBN 书号**能作关键字（书名、作者+出版社都可能重复）。
- 在学生管理的关系数据库中，**存取一个学生信息的数据单位是"记录"**（不是字段、不是文件）。

  **例题**

> **答案：A**。

## 4.6 关系代数（第 10 题的常客）

**必背结论**

- **两类运算**：
  - **传统的集合运算**：**并 ∪、交 ∩、差 −、广义笛卡儿积 ×**。这类运算把关系看成**元组的集合**，以**行为单位**进行；交、并要求参与运算的两个关系**属性个数相同、对应属性域相同**。
  - **专门的关系运算**：**选择 σ、投影 π、连接（自然连接）、除 ÷**，用于表达查询操作。
- **选择的含义**：从关系中选出**满足条件的元组** → 操作的是**行**（横向，结果列数不变）。
- **投影的含义**：从关系中选出**指定的属性列**组成新表 → 操作的是**列**（纵向，结果行数可因去重变少）。**投影是单目运算**。
- **自然连接**：用"等于"比较被连接列的值，在结果中**去掉重复列**，是把两个表"横向拼接"。
- **交**：结果 = 两关系**公共元组**；**并**：结果 = 两关系**所有元组的合并（去掉重复）**；**差**：结果 = 在 R 中但不在 S 中的元组。
- **除**：$R(X,Y) \div S(Y)$ 的结果是 $X$ 上的投影，条件是某 $x$ 的象集包含 $S$ 在 $Y$ 上的投影。

> <img class="callout-badge" src="/media/icons/lightbulb.svg" alt="tip">**看图判运算的五步法**
> 1. **列数变了吗？** 列变少、行也来自原表 → **投影**。
> 2. **行数变少而列没变？** → **选择**（看条件，如"只保留 B=3 的行"）。
> 3. **两个表拼成一个更宽的表？** → **连接/自然连接**（去掉重复列）。
> 4. **结果是两表的公共行？** → **交**；**结果包含两表所有行？** → **并**。
> 5. **结果 = 表 R 去掉表 S 中出现的行？** → **差**。

**真题演示**

> **【2015年3月·10】** 有关系 R 与 T 如下，则由关系 R 得到关系 T 的操作是 ___。
> R：
> 
> | A | B | C |
> |---|---|---|
> | a | 1 | 2 |
> | b | 2 | 2 |
> | c | 3 | 2 |
> | d | 3 | 2 |
>
> T：
> 
> | A | B | C |
> |---|---|---|
> | c | 3 | 2 |
> | d | 3 | 2 |
>
> A）选择　B）投影　C）交　D）并
> **答案：A**。列没变（还是 A、B、C），行变少（只留下 B=3 的两行）→ 选择运算。

> **【2014年3月·9】** 有关系 R 与 S 如下，由关系 R 通过运算得到关系 S，则所使用的运算为 ___。
>
> R：
> 
> | A | B | C |
> |---|---|---|
> | a | 3 | 2 |
> | b | 0 | 1 |
> | c | 2 | 1 |
>
> S：
> 
> | A | B |
> |---|---|
> | a | 3 |
> | b | 0 |
> | c | 2 |
>
> A）选择　B）投影　C）插入　D）连接
> **答案：B**。行数不变、列数变少 → 投影（选出 A、B 两列）。

> **【2015年9月·10】** 有三个关系 R、S 和 T 如下，则由关系 R 和 S 得到 T 的操作是 ___。
>
> R：
> 
> | A | B | C |
> |---|---|---|
> | a | 1 | 1 |
> | b | 2 | 1 |
> | c | 3 | 1 |
>
> S：
> 
> | A | D |
> |---|---|
> | c | 4 |
>
> T：
> 
> | A | B | C | D |
> |---|---|---|---|
> | c | 3 | 1 | 4 |
>
> A）自然连接　B）交　C）投影　D）并
> **答案：A**。按公共属性 A 相等拼接，并去掉重复的 A 列 → 自然连接。

> **【2013年9月·10】** 有三个关系 R、S 和 T，由关系 R 和 S 通过运算得到关系 T，则所使用的运算为 ___。
>
> R：
> 
> | A | B |
> |---|---|
> | m | 1 |
> | n | 2 |
>
> S：
> 
> | A | B |
> |---|---|
> | 1 | 3 |
> | 3 | 5 |
>
> T：
> 
> | A | B | C |
> |---|---|---|
> | m | 1 | 3 |
>
> A）笛卡儿积　B）交　C）并　D）自然连接
> **答案：D**。R 取 A=m,B=1 的元组，S 取 A=1,B=3 的元组，按"R 的 B = S 的 A"取值相连 → 自然连接。

> **【2014年9月·10】** 有三个关系 R、S 和 T，其中关系 T 由关系 R 和 S 通过某种操作得到，该操作为 ___。
>
> R：{(a,1,2), (b,2,1), (c,3,1)}　S：{(d,3,2)}　T：{(a,1,2), (b,2,1), (c,3,1), (d,3,2)}
> A）选择　B）投影　C）交　D）并
> **答案：D**。T 包含 R 与 S 的全部元组 → 并。（若结果只留公共元组则为交。）

> **【2012年9月·6】** 有关系 R 与 S，由关系 R 得到关系 S 的操作是 ___。
>
> R：{(a,1,2), (b,2,1), (c,3,1)}　S：{(c,3,1)}
> A）选择　B）投影　C）自然连接　D）并

> **【2011年9月·9】** 由关系 R 和 S 得到关系 T 的操作是 ___。
>
> R：{(a,1,2), (b,2,1), (c,3,1)}　S：{(a,1,2), (b,2,1)}　T：{(c,3,1)}
> A）自然连接　B）差　C）交　D）并
> **答案：B**。T = R 中减去 S 中出现的元组 → 差。

> **【2012年3月·6】** 由关系 R 和 S 得到关系 T 的操作是 ___。
>
> R：{(a,1,2), (b,2,1), (c,3,1)}　S：{(a,1,2), (d,2,1)}　T：{(b,2,1), (c,3,1)}
> A）自然连接　B）并　C）交　D）差
> **答案：D**。T = R − S。

> **【2011年3月·9】** 由关系 R 和 S 得到关系 T 的操作是 ___。
>
> R(A,B,C)：{(a,1,2), (b,2,1), (c,3,1)}　S(A,B)：{(c,3)}　T(A,B,C)：{(c,3,1)}
> A）自然连接　B）交　C）除　D）并
> **答案：C**。R 与 S 的交、并都等于 R 本身，都不是 T → 是**除**运算：$R \div S$ 取"在 A、B 上分量与 S 全部元组都匹配"的元组。

## 4.7 数据库设计的六阶段

**必背结论**

- 数据库设计的基本思想：**过程迭代、逐步求精**。
- **规范设计法六阶段**（顺序要记牢）：
  1. **需求分析**（建立**数据字典**）
  2. **概念结构设计**（画 **E-R 图**）
  3. **逻辑结构设计**（E-R 图 → 关系模式，规范化）
  4. **数据库物理设计**（存储结构、存取方法）
  5. **数据库实施**（建库、装入数据）
  6. **数据库运行与维护**
- 数据库应用系统中的**核心问题是数据库设计**。

  **例题**

> **答案：A**。

> **【2014年3月·8】** 数据库应用系统中的核心问题是 ___。
> A）数据库设计　B）数据库系统设计　C）数据库维护　D）数据库管理员培训
> **答案：A**。

# 五、易混概念对照总表（考前扫一眼）

| 易混对 | 判别要点 |
|---|---|
| 线性 / 非线性结构 | 一个根 + 每点最多一前一后 = 线性；二叉树、树、图 = 非线性 |
| 循环队列 | 是**线性**结构，是队列的**顺序**存储结构 |
| 双向链表 | 有两个指针，仍是**线性**结构 |
| 顺序 / 链式存储 | 链式多花指针空间、插入删除不移动元素、不能随机存取 |
| 栈 / 队列 | 栈 LIFO（栈底不动）、队列 FIFO（队头队尾共同决定元素个数） |
| 时间复杂度 / 空间复杂度 | 基本运算次数 / 所需存储空间 |
| 二分查找适用面 | 顺序存储 + 有序；**链表不行** |
| 最坏最优排序 / 平均最优排序 | 堆排序 / 快速排序 |
| 结构化 / 面向对象原则 | 自顶向下、逐步求精、模块化、限制 goto ↔ 封装、继承、多态 |
| 内聚 / 耦合 | 内聚看**模块内部**（越高越好）；耦合看**模块之间**（越低越好） |
| 白盒 / 黑盒 | 依据内部逻辑（覆盖、路径） / 依据外部功能（等价类、边界值） |
| 测试 / 调试 | 发现错误（不改） / 诊断并改正（错误定位→改代码→回归测试） |
| 需求分析工具 / 设计工具 | DFD、DD、判定表 ↔ 结构图、PAD、N-S 图、程序流程图 |
| 概念模式 / 外模式 / 内模式 | 全局逻辑结构 / 用户视图（反映用户要求） / 物理存储（对用户透明） |
| E-R 图符号 | 矩形=实体、椭圆=属性、菱形=联系 |
| 联系类型 | 1:1、1:m、m:n（**没有 m:1**） |
| E-R 图所在阶段 | **概念设计**；转关系模式属**逻辑设计** |
| 数据字典建立阶段 | **需求分析**阶段 |
| 候选关键字 | 一个关系应有**一个或多个**；主属性不能为空（实体完整性） |
| 选择 / 投影 | 选**行** / 选**列**（投影是单目运算） |
| 并 / 交 / 差 | 全部元组合并 / 公共元组 / R 中有而 S 中无 |
| 自然连接 | 按公共属性相等拼接并去重复列 |

# 六、考前 10 分钟速记清单

1. **算法四特性**：可行、确定、有穷、有足够情报；**算法 ≠ 程序**。
2. **时间复杂度=基本运算次数，空间复杂度=存储空间**。
3. **线性结构 = 一个根 + 每点最多一前一后**；循环队列、双向链表都是线性结构，二叉树和二叉链表不是。
4. **链式比顺序多花指针空间；链式插入删除不移动元素；链表不能二分查找**。
5. **栈 LIFO，栈底指针不动**；函数调用与递归都靠栈。
6. **队列 FIFO**；循环队列元素个数 = (rear − front + m) mod m；front=rear 可能空也可能满。
7. **二叉树：$n_0 = n_2 + 1$，$n = n_0+n_1+n_2$，深度=最大层次**。
8. **最坏比较次数最少的是堆排序**；快排平均最好但初始有序时退化。
9. **结构化四原则**：自顶向下、逐步求精、模块化、限制 goto；三结构：顺序、选择、循环。
10. **模块独立性：高内聚、低耦合**；内聚在模块内、耦合在模块间。
11. **对象四特点**：标识唯一性、分类性、多态性、继承性（"一致性"是错的）。
12. **软件生命周期**：提出→实现→使用维护→退役；详细设计属**开发阶段**；软件**不会磨损老化**。
13. **软件危机三问题**：成本、质量、生产率。
14. **DFD/DD 属需求分析**，结构图/PAD/N-S/程序流程图属**设计**；SRS 不能当可行性研究依据。
15. **测试=发现错误（白盒看内部逻辑、黑盒看外部功能），调试=诊断并改正**。
16. **DBMS 是操作系统支持下的系统软件**；数据管理三阶段中数据库系统阶段共享最好。
17. **DDL 定义模式、DML 查询增删改、DCL 管完整性/安全/并发/恢复**。
18. **三级模式**：概念（全局逻辑）、外（用户视图）、内（物理存储）；没有"数据模式"。
19. **E-R 图：矩形实体、椭圆属性、菱形联系**；联系只有 1:1、1:m、m:n。
20. **关系代数**：选行=选择、选列=投影、拼表=自然连接、公共元组=交、全部元组=并、R 减 S=差。
21. **一个关系应有一个或多个候选关键字**；能唯一标识记录的属性才能作关键字（ISBN 书号）。
22. **数据字典在需求分析阶段建立，E-R 图在概念设计阶段，转关系模式在逻辑设计阶段**。
